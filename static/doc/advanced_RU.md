# Расширенная конфигурация

В этом документе описаны полезные, но часто пропускаемые настройки: подключение сторонних OpenAI-совместимых моделей, умная маршрутизация smart_mode и подтверждение (автоподтверждение) операций задачи.

---

## 1. Сторонние модели (CUSTOM_URL)

Все текстовые запросы MuseBot используют OpenAI-совместимый формат. Параметр `TYPE` выбирает встроенный адрес API и токен, а **`CUSTOM_URL`, если задан, переопределяет любой встроенный адрес** — поэтому любой OpenAI-совместимый сторонний сервис подключается напрямую.

### Настройка

| Переменная окружения | Описание                                                       |
|----------------------|----------------------------------------------------------------|
| `TYPE`               | Укажите `openai` (используется `OPENAI_TOKEN`, без встроенного адреса) |
| `OPENAI_TOKEN`       | API-ключ сторонней платформы                                   |
| `CUSTOM_URL`         | OpenAI-совместимый базовый URL (обычно заканчивается на `/v1`) |
| `DEFAULT_MODEL`      | Имя текстовой модели по умолчанию (в именовании платформы)     |

Локальный запуск:

```sh
go run main.go -telegram_bot_token=your-telegram-token \
  -type=openai \
  -openai_token=sk-xxx \
  -custom_url=https://open.bigmodel.cn/api/paas/v4 \
  -default_model=glm-4.6
```

Запуск в Docker:

```sh
docker run -d -v /home/user/data:/app/data \
  -e TELEGRAM_BOT_TOKEN="your-telegram-token" \
  -e TYPE="openai" \
  -e OPENAI_TOKEN="sk-xxx" \
  -e CUSTOM_URL="https://open.bigmodel.cn/api/paas/v4" \
  -e DEFAULT_MODEL="glm-4.6" \
  -p 36060:36060 -p 18080:18080 --name my-bot jackyin0822/musebot:latest
```

### Популярные сторонние сервисы

| Сервис                        | CUSTOM_URL                                          |
|-------------------------------|-----------------------------------------------------|
| Zhipu GLM                     | `https://open.bigmodel.cn/api/paas/v4`              |
| Kimi (Moonshot)               | `https://api.moonshot.cn/v1`                        |
| Qwen (режим совместимости DashScope) | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| DeepSeek                      | `https://api.deepseek.com/v1` (или просто `TYPE=deepseek`) |
| Локальный Ollama              | `http://127.0.0.1:11434/v1`                         |
| Шлюз OneAPI / NewAPI          | `http://your-host:3000/v1`                          |

### Примечания

- **Для распознавания изображений нужна vision-модель**: `DEFAULT_MODEL` должен принимать изображения (например, `glm-4.6`, `qwen-vl-*`, `gpt-4o`); стандартная `gpt-3.5-turbo` не поддерживает.
- Команды `/txt_type` и `/txt_model` позволяют менять тип и имя модели на ходу.
- **Генерация** изображений/видео настраивается отдельно (`MEDIA_TYPE`: openai/gemini/vol/aliyun) и не зависит от `CUSTOM_URL`. См. [настройку изображений](./imageconf_RU.md) и [настройку видео](./videoconf_RU.md).

## 2. smart_mode

При включённом `SMART_MODE` (по умолчанию `true`) обычные сообщения сначала проходят классификацию намерения и направляются автоматически:

| Тип сообщения                                              | Маршрут                                     |
|------------------------------------------------------------|---------------------------------------------|
| Простые вопросы, беседа                                    | Прямой ответ, как `/chat`                   |
| Сложные многошаговые задачи (код, исследования, настройки) | Мультиагентный процесс `/task`              |
| «Напоминай мне каждый день в 9…»                           | Автоматически создаётся задание `/cron`     |
| Изображение с просьбой проанализировать                    | `/task` распознавание изображений           |

Во время классификации бот отправляет уведомление «Анализирую ваш запрос...».

```sh
# флаг / переменная окружения
go run main.go -smart_mode=true
SMART_MODE=true ./MuseBot
```

Если выключено, все сообщения обрабатываются как обычный чат, а сложные задачи требуют явной команды `/task`. Ключ конфигурации `smart_mode` также можно переключать на ходу в панели администратора (`http://your-host:18080`).

## 3. Подтверждение операций задачи и автоподтверждение (TASK_AUTO_APPROVE)

По умолчанию при выполнении чувствительных операций в процессе `/task` (изменение настроек бота, запуск команд, расширение файловой песочницы) сначала отправляется запрос на подтверждение:

```
⚠️ Операция задачи требует подтверждения.
Инструмент: bot_config
Цель: config.set smart_mode
Детали: ...
Ответьте `/y` в течение 5 минут для подтверждения или `/n` для отказа.
```

- Ответьте **`/y`** (или `/approve`) — подтвердить, **`/n`** (или `/deny`) — отклонить; можно указать 8-значный код из сообщения;
- Без ответа запрос истекает через 5 минут, и шаг задачи завершается ошибкой;
- У одного пользователя в одном чате может быть только один ожидающий запрос.

### Автоподтверждение

В доверенном окружении можно отключить ручное подтверждение:

```sh
# флаг
go run main.go -task_auto_approve=true

# переменная окружения
TASK_AUTO_APPROVE=true
```

При включённом автоподтверждении все операции инструментов задачи выполняются сразу, без запроса `/y`. Ключ `task_auto_approve` также можно переключать на ходу в панели администратора.

### Замечания по безопасности

- Автоподтверждение означает, что задачи могут изменять настройки бота и выполнять команды из белого списка без подтверждения — включайте только в **частных или доверенных развёртываниях**;
- Даже с автоподтверждением команды shell ограничены белым списком `ALLOWED_COMMANDS`; новые одобренные команды сохраняются в `data/runtime_boundary.json` и действуют после перезапуска.
