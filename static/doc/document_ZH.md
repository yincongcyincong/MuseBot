# 文档识别

向机器人发送文档（txt / pdf / csv / html）并针对内容提问。文档会被解析成纯文本注入 LLM 上下文，因此
DeepSeek 这类纯文本模型也能"读"文档。

## 使用方式

文档全自动处理，无需任何命令：

| 操作 | 行为 |
|---|---|
| **只发** 文档 | 机器人立即自动分析并回复内容总结 |
| 发送文档 **附带** 文字（如 caption） | 立即解析文档并直接回答问题 |
| 后续任何提问 | 文档内容保留在对话上下文中，可以像正常聊天一样持续追问 |

解析出的文档文本会写进对话历史（机器人每次请求都会回放的问答记录），在会话历史窗口内上下文一直有效。

支持格式：`.txt`、`.pdf`、`.csv`、`.html`（含 `.htm`）。其它内容为文本的文件（如 `.bat`、`.diff`、`.log`、`.md`、`.json`、`Makefile`）**默认按纯文本接收和解析**；二进制文件（zip/exe/媒体）会收到明确的拒绝提示。解析出的文本会截断到约 50 KB（保留头尾）以适配模型上下文。

| 平台             | 是否支持 | 说明                                              |
|------------------|:--------:|---------------------------------------------------|

| 🌈 Discord       |    ✅    | `application/pdf` 或 `text/*` 附件                |
| 🔷 Slack         |    ✅    | pdf/txt/csv/html mimetype 的文件分享              |

| 🐋 微信          |    ❌    | 回调模型没有文件消息类型                          |

## 本地媒体存储

自本功能起，会话中接收或生成的图片、视频、文档都以**本地文件**存到 `data/media/{平台}_{会话ID}/`
（每个 IM 会话一个目录）。数据库 `records` 表的 `answer`/`content` 只存相对路径，不再内联 base64。
历史记录兼容读取：改造前的 base64 或 URL 记录仍可正常解码。

### 参数列表

| 参数名                | 类型     | 必填/选填 | 默认值 | 说明                                            |
|-----------------------|----------|-----------|--------|-------------------------------------------------|
| `MEDIA_RETENTION_DAYS` | `int`   | 选填      | `30`   | 删除 N 天前的媒体文件，`0` 表示永不清理。每日任务会清理过期文件及空会话目录；数据库记录保留，引用已清理的文件时会报错提示。 |

> 提示（Docker）：媒体文件位于二进制旁的 `data/` 目录，请挂载卷（如 `-v musebot-data:/app/data`）以保证容器重启后文件不丢失。
